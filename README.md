# 红果短剧 倍速浮点插件（hongguospeed.dylib）

给红果短剧（`com.phoenix.video`）加一个半透明悬浮圆钮，点一下在红果自己那套档位里循环：
**1.0 → 1.25 → 1.5 → 2.0 → 3.0 → 0.75 → 1.0**（0.75/1.0/1.25/1.5/2.0/3.0 全部补齐，和红果倍速菜单一致）。
倍率会记、圆钮位置会记、启动不再黑屏。只做倍速，不碰广告、不碰会员字段。

## 二、导入（巨魔注入器 / TrollFools）

1. 打开巨魔注入器，选中 **红果短剧**。
2. 添加 dylib：选本目录里的 `hongguospeed.dylib`（微信/QQ 传到手机后，在文件 App 里能查到）。
   本插件不依赖 `CydiaSubstrate`，也**不需要** `libJailedShim.dylib` 一起导入。
3. 保存注入，重新打开红果。

## 三、使用

- 屏幕右侧偏上有个半透明圆钮，显示当前倍率数字。
- 点一下切换倍率，顺序 1 → 1.25 → 1.5 → 2 → 3 → 0.75 → 1（档位和红果自己的倍速菜单一一对应）。
- 按住拖动可以挪位置，松手不会切换倍率（拖动和点击是分开的）。**位置也会记住**：拖到哪，下次打开红果就在哪；存的是占屏幕的比例，转屏或换机型都不会跑到屏幕外。
- 数字变成 1 时，恢复红果自己的原始速度，插件不再干预。
- **倍率有记忆**：v9 已实现存档，v10 增强了启动恢复时序；上次点到几，下次打开红果应直接按几播放。本次 v10 是否完全解决冷启动回到 1 倍，需按第四节步骤复测。想取消记忆就把数字点回 1 再退出。
- **长按圆钮 0.6 秒**：弹出一块调试信息（12 秒后自动消失）。行依次是：
  1. `hook N | 实例 M | 跳过 K | 溢出 D | 扫 X ms` —— 挂上了多少个方法、认出几个播放器对象、跳过多少个不能安全代写的、因容量不够被丢掉的、**后台扫描花了多少毫秒**（扫描在后台线程，这个数字再大也不会卡画面）；
  2. `按 目标类 动作方法`（最近 3 次点按钮打到哪里）—— **红果自己的倍速菜单点下去时，它的入口方法名会出现在这里**；
  3. `通知 名字 ×次数 对象类`（名字里带 speed 的 NSNotification）；
  4. `实例1…实例4 <类名>` —— 插件登记下来的播放器对象；
  5. **调用榜**：`类名.方法名 调X 推Y`，后面还会带线索：`于<子类>` = 实际接收者的类和挂的类不同、`=数值` = 最近一次写进去的数字、`收<类名>` = 这个 setter 收的是对象（显示 `收NSNumber` 就能按数字代写）。
     `调X` = 红果自己调了几次，`推Y` = 插件往里写了几次；一条都没有时显示 `没有任何挂点被调用或推送过`。
  **再长按一次会翻页列"最像播放器的那个类"上其余带 speed 的方法。有问题就长按截图发我。**

想要"一打开就默认某个倍率"：把 `SpeedBadge.m` 里 `static int gRateIndex = 0;` 那一行改成对应下标 —— `1`=1.25、`2`=1.5、`3`=2.0、`4`=3.0、`5`=0.75（`0` 是 1.0 不干预），重新走一遍编译。

## 四、真机验证结果

v9 已在 2026-10-01、红果 7.3.9 真机确认：
1. 点圆钮之后**播放速度真的变**，不再是"数字自己在跳、播放器没被写值"；
2. 打开红果**不再"有声音但黑屏"**，画面正常出；
3. 倍率数值能保存，圆钮会显示上次选择的倍率；
4. 把圆钮拖到别处 → 杀掉红果 → 重开 → 停在你拖到的位置。

v10 专门修复“圆钮显示上次倍率，但播放器仍按红果默认 1 倍启动”的时序漏洞，需真机复测：
1. 点到 1.5，正常播放几秒后杀掉红果；
2. 重开红果并播放短剧，不要点圆钮；
3. 确认圆钮显示 1.5，且实际播放速度直接是 1.5；
4. 再点回 1，杀掉重开，确认恢复成红果原始速度。

红果真正控制倍速的入口（长按面板自己报出来的，不是猜的）：
- `TTVideoEngineOwnPlayer.setPlayerPlaybackSpeed:` 和 `TTVideoEngineOwnPlayer.setPlaybackSpeed:`，参数是**对象（`NSNumber`）**，起播、切集、切档位都会调。
- **诱饵**：`TTVideoEngineNetworkPortraitData.setNetSpeed:`、`BDAOVideoNetworkSpeedSample.setSpeed:` —— 名字带 speed 但那是**网速**，往里写倍速只会污染埋点。源码里"只有方法名含 `play` 或挂的类名含 `player` 才允许写值"这条限制就是为它准备的，**别删**。

## 五、为什么源码长这样（改动备忘）

- **静态符号表里的类归属不可信**：脱壳 IPA 里看着像 `-[TTVideoEngine setPlaySpeed:]`，真机上 `class_getInstanceMethod(TTVideoEngine, @selector(setPlaySpeed:))` 返回 NULL；而 `class_copyMethodList` 只返回该类自己实现的方法、不含继承来的。所以改成运行时扫"名字含 `Player` / `Engine` / `Speed` 的类 + 沿继承链"，把挂点装在**真正声明该 selector 的那个类**上。
- **不能只盯名字含 speed/rate 的 setter**：曾经挂上 32 个 void 型 speed/rate 方法、也认出了播放器实例，但用红果自带菜单调到 2.0x 时调用榜全空 —— 说明"猜得更全"没用，得让 App 自己点名。现在每个挂点带调用计数（`调X`/`推Y`），长按面板按调用次数排前 8 名。
- **容量截断会被误读成 App 的事实**：一次面板显示 `hook 96`，而 96 正好等于 `gEntries` 的容量上限，超出部分被静默丢弃，当时据此得出的"倍速不走 ObjC"结论是错的、已作废。现在容量 1024，并且面板显式显示 `溢出 N` —— 任何截断都必须可见。
- **全类扫描绝对不能放主线程**：几万个类、每个方法都 malloc 一次类型串；主线程一停，视频首帧提交不上去，而音频在自己那条线程照常播 —— 症状正好是"有声音、黑屏、过一会出画面"。现在扫描在后台队列（`QOS_CLASS_UTILITY`），主线程只负责建浮钮，面板的 `扫 X ms` 用来复核耗时。
- **只挂 `void` 返回值的方法**：把返回 `double` 的 getter 换成空壳会让调用方读到脏数据；`-(BOOL)setSpeed:` 这类非 void setter、以及结构体参数的方法一律跳过并计入"跳过"。
- **对象参数的 setter 也要登记接收者**：只记录"红果往这个方法塞了什么类"而不登记对象，`推` 永远进不去 OwnPlayer；现在收到 `NSNumber` 就按当前倍速代写。
- **通用祖先类上的挂点是纯噪音**：`NSOperation.start` 实测被调 736 次，会把调用榜挤满；`play/start` 不再挂到通用类，`Track` 只收名字像播放器的对象。
- **持久化存数值和比例，不存下标和坐标**：`HGSpeedRate` 存**倍率数值**（档位表以后怎么改都不会错位，读不到或对不上就回 1.0 不干预）；`HGBadgePos` 存**中心点占屏幕宽高的比例**（转屏、换机型都只会回到同一块相对位置），恢复时套用和拖动一样的边界限制（半径 + 8 的边距、顶部再让出 40）。
- **新登记的播放器会自动补写当前档位**：`Track` 会标记"这是一个新登记出来的播放器对象"，主线程下一次心跳（0.5 秒内）把当前倍率补上去，所以冷启动后不用点第二下。
- **跨线程发布挂点表要加内存屏障**：整条记录写完 → `__sync_synchronize()` → 才让 `gEntryCount++` 被别的线程看到；否则红果自己的调用线程可能读到一条 `orig` 还没填好的半截记录。
- **两个"问路"探针保留着**：`-[UIApplication sendAction:to:from:forEvent:]`（任何按钮点击都要过这里，列出最近 3 次的目标类 + 动作方法）和 `NSNotificationCenter` 的两个 post 方法（记名字里带 speed 的通知）。它们只记录、不改行为，原实现照常调用 —— 以后红果换了倍速通道，靠这两块定位。

## 六、已知限制

- 红果自带倍速菜单显示的数字可能和实际倍率**对不上**：插件在播放器层代写，App 自己不知道。以圆钮上的数字为准。
- 倍速后服务端统计的观看时长与实际播放可能不一致，涉及金币/提现收益，先小额试。
- 只挂 ObjC 层。若红果某天改成走 C++/KMP 内核、或把这些方法名改掉，症状会是"数字在跳但播放器没反应"—— 长按圆钮看调用榜里 `推` 是否为 0，截图发我。
